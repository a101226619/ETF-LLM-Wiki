# LLM Wiki 實際執行與檢查紀錄

## 一、專案介紹

本專案以「美股 ETF 入門」為主題，主要教學對象為對美股投資有興趣的大學生。

使用 LLM Wiki 整理 ETF、QQQ、VOO、投資風險與定期定額等知識，再將 Wiki 內容製作成 12 頁互動式 HTML 教學簡報。

## 二、資料 Ingest 紀錄

本次建立 5 份公開來源的整理檔案，分成兩批處理。

- 第一批：S01、S02
- 第二批：S03、S04、S05

資料以官方來源為優先，保留來源資訊，並整理成 Wiki 主題頁。

目前的 raw 資料為人工整理的來源摘要與原始網址，並非自動擷取的完整文章。

## 三、Graph 與局部 Loop 設計

工作流程：

取得資料 → 分批 Ingest → 來源驗證 → 建立 Wiki → 整理教學大綱 → 產生 HTML → 自動檢查 → 輸出簡報

局部 Loop 設計：

1. 資料不足時，返回資料取得與 Ingest 節點。
2. 來源數字不一致時，返回來源驗證節點。
3. 教學內容有錯誤時，返回內容整理節點。
4. HTML 版面或互動功能有問題時，返回 HTML 修正節點。

每個修正階段最多嘗試三輪，若仍未通過，則記錄問題並停止該部分的生成。

## 五、發現的問題

本次資料整理過程發現，ETF 的費用率可能因資料更新而產生差異。

例如 QQQ 的舊資料曾使用 0.20%，而新版官方資料顯示 0.18%。

如果沒有先驗證資料日期與官方來源，過時數字就可能被寫入 Wiki，再傳遞到 HTML 簡報。

此外，首次上傳 GitHub 時，專案資料夾路徑沒有正確保留，導致檔案集中在根目錄。後續重新上傳資料夾，確認 raw、wiki、scripts、reports 與 slides 的路徑已建立。

## 六、反思與 Workflow 調整

**1. 哪個節點最常出錯？**

目前沒有完整的多輪節點失敗次數統計，因此無法客觀判定哪個節點最常失敗。

但在本次實作中，資料來源驗證是重要的高風險節點；GitHub 檔案上傳與路徑整理則是實際遇到並修正的操作問題。

**2. 發現問題後，把檢查往前移到了哪裡？**

將費用率、資料日期及官方來源的檢查，設計在 Ingest 後、Wiki 內容生成前進行，而不是等 HTML 簡報完成才檢查。

**3. 有沒有修改 Workflow／Graph？為什麼？**

有，在流程設計中明確加入來源驗證節點及局部 Loop 規則。

當來源資訊不一致時，應先返回來源驗證或資料取得節點，而不是重新生成整份 HTML。

這樣可以減少錯誤向後傳遞，並降低不必要的重複生成成本。
